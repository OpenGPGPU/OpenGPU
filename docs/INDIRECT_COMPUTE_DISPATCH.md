# Indirect compute dispatch hardware

The optional GCI1 profile resolves GPU-resident compute arguments before
admitting an ordinary tagged kernel command. It implements the three-uint32
layout and zero-dimension no-work behavior described in OpenGL ES3.1 section17.
This hardware transport is an intermediate H7 capability, not a complete API
implementation. [Khronos specification](https://registry.khronos.org/OpenGL/specs/es/3.1/es_spec_3.1.pdf)

## Submission and discovery

Enable `enableIndirectCompute` consistently in `GpuHostSystemAxi`, `GpuSystem`
and its command router. Opcode14 selects the indirect path. The existing
SOURCE register carries allocation VA base, BYTES carries allocation length,
and WIDTH carries argument byte offset. Kernel PC, kernarg and local dimensions
retain their direct-command meaning and are snapshotted with the command.
Existing event and DMA dependencies gate argument reads, not only later kernel
launch. A reused DMA producer ID clears its previous dependency token.

The read-only GCI1 block occupies0x340..0x35f. It reports its exact magic, eight
words, implemented feature flags, opcode14, twelve argument bytes, alignment4,
full uint32 group-count range and the elaborated CU local-item capacity. Disabled
profiles leave it unmapped. Global capability bit1 stays reserved; no occupied
legacy capability bit is repurposed. The hardware header is generated by
`EmitComputeIndirectAbi`; existing global opcode/status constants also remain
in `gpu_abi.h`. Driver/compiler implementation is outside this hardware plan.

## Argument and owner lifetime

`IndirectDispatchReader` captures the view and checks its allocation end,
offset-plus-twelve and absolute argument span with33/34-bit arithmetic before
offering memory. Both offset and absolute start must be four-byte aligned.
An exclusive end of2^32 is legal; wrapped allocations/spans fail with status12
and no memory read. One or two64-byte cache-line reads pass through Sv32 and
shared L2, each using a dedicated ID owner. Only the validated twelve-byte
logical span is interpreted. Cache-line fills retain normal page permissions.
Any translation or physical read fault completes with status13; a successful
prefix cannot launch a partial kernel. All three uint32 values are retained.
Any zero dimension completes successfully without launching a CU.

The router keeps the command ID reserved through public completion acceptance.
Its argument owner blocks memory-dependent graphics while arguments are queued
or being fetched; after the kernel command is handed off, compute follows the
existing scheduling/ownership path and does not retain an unnecessary DMA owner.

Controlled reset stops new reads and latches cancellation. An offered physical
request remains stable until accepted and its actual reply drains. Cancellation
prevents a second, not-yet-offered line read. The router drops its unlaunched
argument state only as part of the existing drained command-path reset. An
already launched kernel follows normal compute retirement. This supplies no
cycle deadline for an unresponsive bus or kernel.
