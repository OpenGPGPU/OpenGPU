# Mobile GPU hardware capability inventory

This inventory supports H0 and the
[hardware alignment plan](MOBILE_GPU_HARDWARE_ALIGNMENT.md). It records hardware
contracts and evidence gaps; it does not advertise an API version. Compiler,
driver and API object management remain separate work, while the hardware
interfaces they require remain in scope. The device compiler is the sibling
`../llvm-project` branch `opengpu`; its status and the ISA/ABI it already
consumes are in [LLVM_TOOLCHAIN_PLAN.md](LLVM_TOOLCHAIN_PLAN.md).

`Partial` means relevant RTL exists but the complete requirement is unproven.
`Open` means the inspected production contract does not provide the required
interface or its verification. A module or capability bit alone cannot close a
row. Every row needs a frozen source/configuration, an independently checked
result and integrated fault/ordering evidence before promotion to verified.

The normative baselines are [GLES 3.0.6](https://registry.khronos.org/OpenGL/specs/es/3.0/es_spec_3.0.pdf),
[GLES 3.1](https://registry.khronos.org/OpenGL/specs/es/3.1/es_spec_3.1.pdf) and
[GLES 3.2](https://registry.khronos.org/OpenGL/specs/es/3.2/es_spec_3.2.pdf).
The tables group requirements for implementation. They must be expanded into
individual format, limit and operation cases before H6–H8 closure; they are not
an exhaustive specification-clause or conformance-test mapping.

The requirement groups below follow the GLES 3.0 specification's vertex,
rasterization, texture, framebuffer and synchronization chapters. Current-state
assessments are engineering conclusions from the linked RTL, not Khronos claims.

## Selected capacity blockers

The GLES 3.0 minimum values below come from its implementation-dependent limit
tables. Each needs a discoverable implemented limit and a boundary test; a wide
address field is insufficient evidence.

| Capacity | GLES 3.0 minimum | Current production contract | Remaining evidence |
|---|---|---|---|
| Vertex attributes | 16 | VIF/VSH have 16 descriptor slots; VIC covers all-enabled inputs and the full 128-thread/64-component interface with controlled spill | Broader native capacity combinations and general allocation/resource ownership |
| Draw buffers | 4 | FSH/TCOL/TRND provide four typed output locations with masks, late tests and blending; native typed/binned hosts publish four locations with exact sources/resolves | Broader native integer/format/state combinations, general resource ownership and API integration |
| Color attachment bindings | 4 | TCOL/TRND expose four bounded typed color views plus depth/stencil; native image descriptors carry source and resolve views | Full format-specific native admission, allocation/alias ownership and capacity combinations |
| 2D and cube dimensions | 2048 each | Native 2D extent fields; TIA covers 2048-square views and all six cube faces at the address component | GPU descriptors, cube selection/filtering, all levels/formats and native bounds/fault integration |
| Array layers | 256 | TIA covers every layer and a full 2048-square 256-layer RGBA8 array ending at 4 GiB | GPU binding and mip tables, layer selection/filtering and native provenance/visibility |
| 3D dimension | 256 | TIA covers every slice and a full 256-cubed volume at the address component | GPU descriptors, 3D coordinate/filtering operations and native memory/fault ownership |

The [shader and framebuffer capacity contract](MOBILE_GPU_RESOURCE_LIMITS.md)
adds individual normative uniform, varying, texture-unit and renderbuffer rows,
their implemented discovery paths and missing boundary evidence. Thirty-two
resident bindings per native stage are checked at the exclusive 4 GiB table
boundary. [Typed renderer capacity](NATIVE_UNIFORM_RENDERER_CAPACITY.md) now
checks full uniform/interface composition and sixty-four-component fragment
consumption at two and four CUs. Complete product and full-capacity binned runtime, general
coherence, broader native varying combinations and full-size framebuffer
capacity remain open under H6 and the later capability milestones. The
[H0 acceptance record](MOBILE_GPU_MILESTONE_ACCEPTANCE.md#h0-acceptance-2026-10-27)
closes the contract and measurement foundation; it does not close the gaps
recorded by that contract. Proposal storage budgets and CU lane/warp counts
cannot substitute for shader-visible limits.
